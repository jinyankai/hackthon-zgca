# 客户视角补充测试用例：情绪降噪能力扩展 10 条

## 使用说明

本文件用于补充测试模型是否能处理更丰富的一线高情绪输入场景。重点不只是“去掉脏话”，而是测试模型是否能：

1. 保留真实业务风险。
2. 识别复杂情绪，例如焦虑、恐惧、羞辱感、悲伤、反讽、群体不满。
3. 提取显性诉求和隐性诉求。
4. 给服务者具体下一步动作。
5. 不越权、不乱承诺、不替任何一方判责。
6. 在必要时提示升级主管、医生、负责人或安全流程。

## 推荐输出结构

```json
{
  "filtered_text": "",
  "emotion_level": "calm | dissatisfied | angry | extreme | sarcastic | anxious | grief | fear | shame",
  "emotion_score": 1,
  "explicit_request": "",
  "implicit_need": "",
  "risk_flags": [],
  "suggested_actions": [],
  "agent_protection_tip": "",
  "suggested_reply": "",
  "original_visible": true,
  "approval_needed": true
}
```

## 用例 1：医疗前台等待过久 + 病情焦虑

### 客户输入

```text
我爸胸口不舒服都等半小时了！你们到底有没有人管？要是耽误了你们负责吗？
```

### 场景

医院/诊所导诊或前台，一线人员不是医生，但需要处理焦虑家属。

### 期望输出要点

```json
{
  "filtered_text": "家属表示患者胸口不适并已等待约半小时，对等待时间非常焦虑，担心延误处理。",
  "emotion_level": "anxious",
  "emotion_score": 5,
  "explicit_request": "希望患者尽快获得评估或处理，并确认当前排队/分诊状态。",
  "implicit_need": "需要确认患者没有被忽视，并获得明确的安全处理路径。",
  "risk_flags": ["医疗焦虑", "疑似急症", "等待过久", "责任风险"],
  "suggested_actions": [
    "不要自行判断病情严重程度",
    "立即确认是否需要分诊护士或医生复核",
    "说明当前能做的是通知专业人员评估",
    "记录家属反馈和等待时间"
  ],
  "agent_protection_tip": "服务者不能承诺诊断或结果，也不能说“没事”；应尽快升级给有医疗判断权限的人。",
  "suggested_reply": "我理解您现在很担心。胸口不舒服这种情况需要由专业人员判断，我现在马上帮您联系分诊护士/医生复核，同时确认目前排队状态。"
}
```

### 重点检查

- 不能只说“请耐心等待”。
- 不能让前台做医疗判断。
- 必须识别“疑似急症/责任风险”。

## 用例 2：餐饮过敏风险 + 强烈不信任

```json
  "emotion_level": "fear",
  "emotion_score": 5,
  "explicit_request": "确认餐品是否含花生，并要求处理食品安全问题。",
  "implicit_need": "需要确保孩子安全，并确认商家重视过敏风险。",
  "risk_flags": ["食品过敏", "儿童安全", "食品安全", "严重投诉风险"],
  "suggested_actions": [
    "提醒客户不要继续食用该餐品",
    "核对订单备注和出餐记录",
    "立即升级门店负责人或食品安全负责人",
    "根据平台规则处理退款、重做或后续跟进"
  ],
  "agent_protection_tip": "不要争辩是否真的过敏，也不要让客户继续尝试食用。先处理安全和升级。",
  "suggested_reply": "这个情况我会优先处理。请先不要让孩子继续食用这份餐品。我现在马上核对您的备注和出餐记录，并升级给门店负责人确认餐品成分和后续处理方式。"

```

### 重点检查

- 必须识别食品安全和过敏风险。
- 不能只说“给您换一份”。
- 不能要求客户自行判断是否安全。

## 总体回归检查清单

- [ ] 是否覆盖医疗、餐饮、酒店、托育、医美、保险、物业、旅游、出行、社工等多行业？
- [ ] 是否能识别焦虑、恐惧、羞辱、悲伤、愤怒、群体不满？
- [ ] 是否在高风险场景中建议升级？
- [ ] 是否避免越权诊断、越权承诺或越权赔偿？
- [ ] 是否保留业务风险，而不是只做礼貌改写？
