# 客户视角测试用例：高情绪输入降噪能力测试

## 测试目标

用于验证模型是否真的具备“客户高情绪输入降噪”的能力，而不是简单把脏话删掉、把句子改礼貌。

模型应该做到：

1. 去除或折叠攻击性表达。
2. 保留真实情绪强度。
3. 保留业务风险，例如退款、投诉、曝光、消协、差评、报警等。
4. 提取显性诉求和隐性诉求。
5. 给出服务者下一步动作建议。
6. 在必要时提醒服务者保护边界或升级主管。
7. 不替客户洗白，也不替服务者判责。

## 推荐输出结构

每条客户输入建议输出以下字段：

```json
{
  "filtered_text": "",
  "emotion_level": "calm | dissatisfied | angry | extreme | sarcastic | anxious | grief",
  "emotion_score": 1,
  "explicit_request": "",
  "implicit_need": "",
  "risk_flags": [],
  "suggested_actions": [],
  "agent_protection_tip": "",
  "suggested_reply": "",
  "original_visible": true,
  "approval_needed": true
}
```

## 评分规则

| 维度 | 通过标准 |
|---|---|
| 降噪准确性 | 攻击性语言被处理，但业务事实没有被删掉 |
| 情绪保真 | 不把强烈愤怒弱化成“有点不满” |
| 风险保留 | 投诉、退款、曝光、举报、辱骂等风险标签必须保留 |
| 诉求提取 | 同时提取显性诉求和隐性诉求 |
| 动作建议 | 给服务者具体下一步，而不是只说“安抚客户” |
| 边界保护 | 遇到辱骂、威胁、极端表达时提醒服务者保护边界 |
| 回复自然度 | 建议回复应具体、真诚、有动作，不是模板客服腔 |

## 用例 1：暴怒催单 + 退款投诉威胁

### 客户输入

```text
等了四十分钟了还没到！你们配送是用爬的吗？？再不来我就退款投诉！
```

### 期望输出要点

```json
{
  "filtered_text": "客户已等待约四十分钟，对配送延迟非常不满，并表示如果继续延迟将申请退款和投诉。",
  "emotion_level": "angry",
  "emotion_score": 4,
  "explicit_request": "确认订单当前状态和预计送达时间；如无法及时送达，希望退款或投诉处理。",
  "implicit_need": "需要确定性、解释和被认真处理的感觉。",
  "risk_flags": ["配送超时", "退款", "投诉"],
  "suggested_actions": [
    "查询订单当前位置和配送状态",
    "确认预计送达时间",
    "如确实超时，说明可选处理路径，例如继续等待、退款规则或补偿规则"
  ],
  "agent_protection_tip": "不要回应讽刺或攻击性表达，先处理订单状态和退款投诉风险。",
  "suggested_reply": "我理解您已经等了四十分钟会很着急。我现在先帮您确认订单位置和预计送达时间，如果确实无法及时送达，我会同步告诉您可以选择的处理方式。"
}
```

### 重点检查

- 不能只输出“客户询问预计送达时间”。
- 必须保留“退款”和“投诉”风险。
- 推荐回复不能只有“请您耐心等待”。

### 失败示例

```text
过滤后：客户想知道什么时候送达。
建议回复：您好，感谢您的反馈，我们会尽快处理，请您耐心等待。
```

## 用例 2：极端辱骂 + 消协举报威胁

### 客户输入

```text
你们全家都是废物！收了钱不办事，骗子公司！我要去消协举报你们，让你们全部下岗！

  "filtered_text": "客户对服务结果极度不满，认为付费后问题没有得到处理，并表示可能向消费者协会举报。",
  "emotion_level": "extreme",
  "emotion_score": 5,
  "explicit_request": "要求解释服务未达到预期的原因，并给出解决方案。",
  "implicit_need": "需要看到服务方正在承担问题、给出明确路径，而不是继续被忽视。",
  "risk_flags": ["人身攻击", "消协举报", "服务不满意", "升级投诉"],
  "suggested_actions": [
    "先确认客户具体订单或服务事项",
    "说明可以核查的问题范围",
    "必要时升级主管处理",
    "保留事件记录"
  ],
  "agent_protection_tip": "原文包含人身攻击，建议默认折叠。服务者不需要回应辱骂内容，如对方持续攻击，应使用边界话术或升级主管。",

}
```

### 重点检查

- 不能把“人身攻击”完全消失。
- 必须提示服务者保护边界。
- 不能输出卑微道歉，例如“都是我们的错”。

## 回归测试检查清单

每次模型更新后，至少检查以下问题：

- [ ] 是否把强烈情绪弱化成普通咨询？
- [ ] 是否遗漏退款、投诉、举报、曝光等风险？
- [ ] 是否遗漏辱骂、人身攻击、威胁等服务者保护信号？
- [ ] 是否能识别反讽？
- [ ] 是否能处理中英混杂？
- [ ] 是否给出具体下一步动作？
- [ ] 是否避免替任何一方判责？
- [ ] 是否保留人工确认？
- [ ] 是否生成自然、具体、有边界的建议回复？
