# AI 情绪护盾 Demo 启动与操作手册

这份文档用于黑客松现场演示。目标不是讲架构，而是让任何队友在一台机器上快速启动，并按固定脚本稳定演示“客户输入 -> AI 降噪 -> 客服回复 -> AI 优化 -> 人工确认 -> 对话总结”。

## 1. 演示目标

- 展示客户高情绪投诉进入系统后，客服侧看到的是可处理的信息，而不是直接承受攻击性表达。
- 展示客服可以查看原文，但系统默认先给出过滤表达、核心诉求、风险标签、建议回复和情绪电量。
- 展示客服输入口语化回复后，AI 会改写为专业、平等、不卑微的话术，再由客服手动确认发送。
- 展示对话结束后，AI 自动生成复盘，并在检测到强烈恶意时给客服疏导和鼓励。
- 展示语音输入只是入口之一，失败时可立即回退到文本或预置脚本。

## 2. 环境准备

在仓库根目录执行：

```powershell
cd E:\zgca\hackthon-zgca
```

安装后端依赖：

```powershell
python -m pip install -r backend/requirements.txt
```

安装前端依赖：

```powershell
npm --prefix frontend install
```

可选：启用真实 LLM。新建或检查 `backend/.env`：

```env
LLM_PROVIDER=deepseek_anthropic
DEEPSEEK_API_KEY=你的 key
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
LLM_MODEL=deepseek-chat
LLM_TIMEOUT_SECONDS=12
```

如果没有 key，不需要配置 `.env`。系统会使用 mock fallback，仍然可以完整演示。

## 3. 启动服务

打开第一个终端，启动后端：

```powershell
npm run dev:backend
```

看到类似内容即可：

```text
Uvicorn running on http://0.0.0.0:8000
```

打开第二个终端，启动前端：

```powershell
npm run dev:frontend
```

看到类似内容即可：

```text
Local: http://localhost:3000
```

浏览器打开：

```text
http://127.0.0.1:3000
```

检查后端状态：

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8000/health
```

返回中 `llm` 为 `live` 表示真实模型可用；为 `mock` 表示降级演示模式。

## 4. 推荐演示顺序

### A. 自动演示模式

这是最稳的现场入口。

1. 点击页面顶部的“随机自动播放”。
2. 系统会从 `frontend/mocks/dialogueCorpus.json` 的 `autoScripts` 中随机抽取一组多轮对话。
3. 页面会自动播放客户发言、AI 下行降噪、客服草稿、AI 上行优化、人工确认发送。
4. 自动播放结束后，客服侧会出现对话复盘和疏导建议。
5. 点击“回到手动演示”，即可清空状态并回到人工操作模式。

现场口播重点：

- “这里不是生成一个随机故事，而是从本地固定语料库抽取多轮高压服务场景，保证演示可控。”
- “AI 没有隐藏原文，客服仍然可以点击查看。”
- “AI 不代替客服发送，最终发送权仍在客服手里。”
- “结束对话后，系统不仅总结客户诉求，也对客服做压力缓冲。”

### B. 手动文字演示

适合评委想看输入输出细节时使用。

1. 在客户侧输入：

```text
你们到底会不会送？半小时了还没到！再不来我就投诉退款！
```

2. 点击发送。
3. 客服侧观察：
   - 过滤表达
   - 核心诉求
   - 情绪等级
   - 风险标签
   - 建议回复
   - 情绪电量变化
4. 点击“查看原文”，证明系统不隐藏信息。
5. 在客服草稿输入：

```text
我帮你看一下，别急。
```

6. 点击“AI 优化”。
7. 检查优化后回复，再点击“确认发送”。
8. 点击“结束对话”，查看 AI 复盘和客服疏导。

### C. 客户语音演示

1. 客户侧点击语音按钮。
2. 说出：

```text
你们到底会不会送？半小时了还没到！再不来我就投诉退款！
```

3. 转写结果会进入输入框，但不会自动发送。
4. 检查或微调文本后，点击发送。
5. 如果浏览器权限、麦克风或网络导致识别失败，点击“使用演示语音文本”兜底。

现场口播重点：

- “语音只是输入方式，系统真正处理的是最终文本。”
- “转写结果先进入输入框，客户确认后才发送，避免误识别直接进入客服流程。”

### D. 客服语音草稿演示

1. 客服侧点击语音输入。
2. 说出：

```text
我帮你看一下，别急。
```

3. 系统会把转写结果填入客服草稿框。
4. 如果出现轻微误识别，可手动编辑后再点“AI 优化”。

误识别处理策略：

- 转写不自动发送，必须人工确认。
- 常见客服词汇在前端有轻量纠错，例如“退快”修正为“退款”、“核食”修正为“核实”。
- 现场失败时，直接切换到文本输入或预置脚本，不让语音链路拖垮 demo。

## 5. 本地语料库说明

固定语料库位置：

```text
frontend/mocks/dialogueCorpus.json
```

结构：

```json
{
  "manualScenarios": [],
  "autoScripts": []
}
```

- `manualScenarios`：客户侧手动场景按钮使用。
- `autoScripts`：自动演示播放器随机抽取使用，每组脚本包含多轮 `customerText` 和 `agentDraft`。

新增自动演示场景时，只需要往 `autoScripts` 添加一组：

```json
{
  "id": "new-demo-id",
  "title": "新场景标题",
  "description": "一句话说明这个场景展示什么",
  "turns": [
    {
      "customerText": "客户第一轮输入",
      "agentDraft": "客服第一轮草稿"
    }
  ]
}
```

## 6. 现场故障处理

- 前端打不开：确认 `npm run dev:frontend` 正在运行，并访问 `http://127.0.0.1:3000`。
- 后端不通：确认 `npm run dev:backend` 正在运行，并检查 `http://127.0.0.1:8000/health`。
- LLM 慢或失败：不用停演示，系统会 fallback 到 mock 输出。
- 语音识别失败：点击演示语音文本，或者直接使用手动文字输入。
- WebSocket 断开：刷新页面；必要时重启前后端。
- 自动演示跑乱：点击“回到手动演示”，再重新点击“随机自动播放”。

## 7. 演示前检查清单

- 后端健康检查可访问。
- 前端页面可打开。
- 客户侧能发送一条文字消息。
- 客服侧能看到 AI 降噪结果。
- 客服草稿能成功 AI 优化。
- “确认发送”后客户侧能看到回复。
- “结束对话”后能看到复盘。
- “随机自动播放”能自动跑完整流程。
- “回到手动演示”能清空状态。

## 8. 不要现场临时做

- 不要临时改 prompt。
- 不要现场新增复杂多轮脚本。
- 不要把语音识别作为唯一入口。
- 不要解释模型 API 细节太久。
- 不要在演示中等待长时间 LLM 返回；超时就使用 mock fallback。
